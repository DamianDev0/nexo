# 2.2 — Empresas sobre el motor + primer objeto propio

> Tamaño M · Depende de: 2.1 (A1–A6, B1–B2) · Paralelo con 2.3 y 2.5

## Objetivo

1. **Empresas** como segundo objeto estándar completo sobre el motor: tablero, vistas, filtros, edición en línea, import, archivo, fusión y ficha, reutilizando `widgets/records-board` y `widgets/record-page` sin copiar código de Contactos.
2. **Primer objeto propio real** ("Inmuebles") instalado desde plantilla en un tenant de inmobiliaria, para validar en producción que 2.1 cumple su promesa.

**Criterio de salida:** en un tenant inmobiliario se abre Empresas y Inmuebles desde el menú, se crea una empresa con NIT válido, se vincula un contacto y un inmueble como "Propietario", y el tablero de Empresas guarda una vista compartida — con cero componentes nuevos específicos de tablero.

## 1. API

### 1.1 Migración `0053_companies_engine`

```sql
ALTER TABLE "${schema}".companies
  ADD COLUMN IF NOT EXISTS merged_into_id UUID REFERENCES "${schema}".companies(id),
  ADD COLUMN IF NOT EXISTS search_text TEXT GENERATED ALWAYS AS (
    nexo_unaccent(lower(coalesce(name,'') || ' ' || coalesce(nit,'') || ' ' || coalesce(email,'') || ' ' || coalesce(city,'')))
  ) STORED;
CREATE INDEX IF NOT EXISTS "idx_${schema}_companies_search" ON "${schema}".companies USING GIN (search_text gin_trgm_ops);
CREATE INDEX IF NOT EXISTS "idx_${schema}_companies_active_created" ON "${schema}".companies (is_active, created_at DESC, id);
CREATE INDEX IF NOT EXISTS "idx_${schema}_companies_assigned" ON "${schema}".companies (assigned_to_id) WHERE is_active;
CREATE INDEX IF NOT EXISTS "idx_${schema}_companies_city" ON "${schema}".companies (city) WHERE is_active;
CREATE INDEX IF NOT EXISTS "idx_${schema}_companies_tags" ON "${schema}".companies USING GIN (tags);
```

### 1.4 Reglas colombianas

- NIT se guarda sin puntos ni DV en `nit`, DV en `nit_dv`; `normalizeDocumentNumber` + validación módulo 11 en DTO y en el validador de import.
- Unicidad: índice existente `uq_companies_nit` (activas). El probe y la fusión usan NIT normalizado.

## 5. Pruebas específicas

- NIT: válidos/ inválidos con DV, con puntos/guiones, persona natural vs jurídica.
- Fusión: mueve `contacts.company_id`, `deals.company_id`, `activities.company_id`, `record_associations` donde la empresa es origen o destino.
- Aislamiento: `/companies/counts`, `/companies/:id/merge`, `/companies/views`, `/companies/workspace`, import.
- Regresión: Contactos journey + power-user en cada PR web.
